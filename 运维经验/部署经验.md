## 一、部署架构

```
用户浏览器 → Nginx:80 (apehub.finecv.cn) → uvicorn:8000 (127.0.0.1)
                                                    ↓
                                               MySQL (apehub 库)
```

- **Nginx 反代**：监听 80 端口按域名分发，proxy_pass 到 127.0.0.1:8000
- **systemd 管理 uvicorn**：单 worker（插件热拔插运行态是进程本地的）
- **启动参数**：`--proxy-headers --forwarded-allow-ips 127.0.0.1`（反代场景还原真实客户端 IP）

### 为什么不用 80 端口直连？
服务器上 Nginx 在跑其他项目，不能停。反代模式可以多域名共存。

### 为什么不用宝塔 Python 项目管理器管进程？
宝塔用系统 Python 启动项目，不认项目虚拟环境 `.venv`，导致 `No module named uvicorn`。systemd 直接管更可靠，宝塔只用来查看日志和文件管理。

## 二、安装向导机制（WordPress 式）

### 核心流程
1. 首次访问 → 检测无 `setup.lock` → 进入 setup 模式（只挂 /setup 路由）
2. 安装向导三步：数据库配置 → 站点与管理员 → 安装
3. 安装时：写 `.env` → 建表 → 写 `setup.lock`（不 seed）
4. 用户重启服务 → 新进程加载 .env 中的 JWT_SECRET → 执行 seed（加密密钥正确）
5. 前端轮询 `/setup/api/status` 返回 404 → 判定重启完成 → 跳转首页

### 关键设计决策：seed 延迟到重启
安装进程内写完 .env 后，JWT_SECRET 已更新但进程内存中还是旧值。Fernet 密钥派生自 JWT_SECRET，如果在安装进程内 seed，加密的密文用旧密钥，重启后新密钥解不开。所以安装只建表不 seed，重启后新进程 seed 用新密钥加密。

### 关键文件
- `backend/src/setup_wizard/state.py` — 安装状态管理（.env 写入、lock 检测）
- `backend/src/setup_wizard/api.py` — 安装向导 API（test-db、install、status）
- `backend/src/setup_wizard/setup.html` — 安装向导前端页面（纯 HTML+JS，无依赖）
- `backend/src/main.py` — lifespan 分流 setup/normal 模式

## 三、踩过的坑

### 3.1 宝塔环境准备失败
- **现象**：宝塔「添加 Python 项目」时环境准备失败
- **根因**：uwsgi 编译缺 python3-devel 头文件
- **修法**：`yum install python3-devel`，或直接跳过宝塔的虚拟环境创建，手动建

### 3.2 `python3: No module named uvicorn`
- **现象**：宝塔启动项目报错找不到 uvicorn
- **根因**：宝塔用系统 Python 而非项目 .venv 启动
- **修法**：不用宝塔管进程，用 systemd service 直接指向 .venv/bin/uvicorn

### 3.3 `address already in use` :80
- **现象**：服务绑 80 端口失败
- **根因**：Nginx 已占 80
- **修法**：服务退到 127.0.0.1:8000，Nginx 反代

### 3.4 Nginx 502
- **根因**：宝塔建 Python 项目时自动生成 `python_apeadmin.conf` 抢占域名
- **修法**：`mv python_apeadmin.conf python_apeadmin.conf.disabled`

### 3.5 外网 80 不可达
- **根因**：腾讯云安全组未放行 80
- **修法**：控制台加入站规则 TCP:80 允许 0.0.0.0/0

### 3.6 本地 curl 返回 000
- **根因**：本机 HTTP 代理 `http_proxy=http://::1:7890` 干扰
- **修法**：`no_proxy="*" curl ...`

### 3.7 SPA 路由 404（/admin/login 返回 Not Found）
- **根因**：FastAPI `StaticFiles` 挂载后，找不到文件直接 404，不走 fallback 路由
- **修法**：自定义 `SpaStaticFiles(StaticFiles)` 子类，`get_response` 捕获异常时 fallback 到 `index.html`

### 3.8 登录跳转 404（window.location.href = '/login'）
- **根因**：前端 401 拦截器用 `window.location.href = '/login'`，绕过了 Vue Router base（/admin/）
- **修法**：改为 `window.location.href = '/admin/login'`

### 3.9 验证码明文返回
- **根因**：验证码接口直接返回 `"code":"9393"` 明文
- **修法**：后端改为返回 SVG 图片（base64 data URI），不返回明文 code

### 3.10 解压多套一层目录
- **现象**：部署包解压后路径变成了 `/www/wwwroot/apehub/apeadmin-deploy-base-.../backend`
- **修法**：打包时用扁平结构（tar -C 直接打包内容，不带版本号目录）

## 五、systemd 服务配置

```ini
[Unit]
Description=ApeAdmin Backend (FastAPI)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/www/wwwroot/apeadmin
ExecStart=/www/wwwroot/apeadmin/.venv/bin/uvicorn src.main:app --host 127.0.0.1 --port 8000 --workers 1 --proxy-headers --forwarded-allow-ips 127.0.0.1
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1
StandardOutput=append:/var/log/apeadmin/app.log
StandardError=append:/var/log/apeadmin/app.log

[Install]
WantedBy=multi-user.target
```

## 六、Nginx 反代配置

```nginx
server {
    listen 80;
    server_name apehub.finecv.cn;

    client_max_body_size 100m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }
}
```

## 七、日志配置

### 日志文件
- 路径：`/var/log/apeadmin/app.log`
- systemd 的 stdout/stderr 都写入此文件（`StandardOutput=append:` + `StandardError=append:`）

### 日志轮转
- 配置：`/etc/logrotate.d/apeadmin`
- 策略：每天切割、保留 30 天、gzip 压缩、`copytruncate`（不中断服务）

### 宝塔查看
宝塔面板 → Python 项目 → apeadmin → 设置 → 项目日志 → 路径填 `/var/log/apeadmin`

## 九、本次修复记录

### 修复 1：SPA fallback（main.py）
- **问题**：`StaticFiles` 挂载后 `/admin/login` 等 SPA 路由返回 404
- **方案**：自定义 `SpaStaticFiles` 子类，文件找不到时 fallback 到 `index.html`

- **问题**：401 拦截器 `window.location.href = '/login'` 跳到不存在的路径
- **方案**：改为 `/admin/login`

### 优化 3：登录页中文化 + 去除装饰内容
- 登录页改为中文（登录/账号/密码/验证码等）

- 去除底部 `admin / admin123` 默认密码提示（安装时设的密码不一定相同）

- **问题**：接口直接返回明文 `"code":"9393"`
